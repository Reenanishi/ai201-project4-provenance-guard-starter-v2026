## 1. The path

1. **Submit the text:** A writer submits their writing along with their `creator_id` through the `POST /submit` endpoint.

2. **Validate the input:** The system checks whether the request contains valid text and a creator ID. If information is missing or invalid, it returns an error.

3. **Analyze the text using the AI model:** The `detector.py` file examines the writing using a local language model and generates a score indicating how likely the text is to be AI-generated.

4. **Analyze the writing style:** The `stylometry.py` file measures sentence-length variation, vocabulary diversity, and punctuation patterns to produce a second score.

5. **Combine the two signals:** The `scoring.py` file combines the model score and writing-style score to calculate an overall score and determine the prediction's confidence.

6. **Generate a label:** Based on the combined score and configured thresholds, the system selects one of three labels: high-confidence AI, high-confidence human, or unsure.

7. **Save and return the results:** The system records the submission and its scores in the audit log. It then returns a JSON response containing the `content_id`, prediction, confidence score, and reader-friendly label.

## 2. The two signals

### Signal one — the model (`detector.py`)

**What it measures:**
The model analyzes how predictable the submitted text is using a pretrained GPT-2 language model. It calculates a score indicating how closely the writing matches patterns that the model considers AI-like.

**Why that might differ between human and AI writing:**
AI-generated writing often follows common language patterns and may produce sentences that are more predictable. Human writing can contain unusual word choices, personal expressions, and different sentence structures. These differences may help the model distinguish between AI-generated and human-written text.

**What it can't see (the blind spot):**
The model cannot identify the actual author of the text. A human writer who uses formal language or predictable sentence structures might incorrectly receive a high AI score. Similarly, AI-generated text that has been edited or rewritten may appear human-written.



### Signal two — style (`stylometry.py`, yours to build)

**What it measures:**
This signal analyzes the writing style by examining sentence-length variation, vocabulary diversity, and punctuation usage. It measures these characteristics and combines them into a score.



**Why that might differ between human and AI writing:**
Human writers may naturally use different sentence lengths, varied vocabulary, and irregular punctuation patterns. AI-generated writing may sometimes have more consistent sentence structures and predictable writing patterns. These differences can provide another signal about the text's possible origin.



**What it can't see (the blind spot):**
Writing style alone cannot prove whether a human or AI created the text. Some humans write in a very consistent style, while AI-generated text can imitate human writing patterns. Short passages may also provide too little information for reliable style analysis.

## 3. Trace the false positive

<!-- A real writer submits real work. Your system calls it AI. Follow them
     through the service: what score did they get, what did the label say,
     what can they do about it? -->

**Who they are:**
A college student writes an original essay for a creative writing assignment. The student spends several hours researching, writing, and editing the essay before submitting it to a writing website that uses Provenance Guard.

**What score they get and why:**
The system gives the student's essay an AI-likelihood score of 0.91, even though the student wrote it themselves. This happens because the essay uses formal language, consistent sentence structures, and predictable vocabulary. Both detection signals interpret these writing patterns as AI-like, resulting in a false positive.

**What the label says to them:**
Our system believes this text was likely generated by AI. However, this is only a prediction and does not prove that AI was used. If you believe this result is incorrect, you can submit an appeal for review.

**What they can do about it:**
The student can submit an appeal through the POST /appeal endpoint by providing their content_id and explaining why the prediction is incorrect. They may mention that they wrote the essay themselves and have earlier drafts as evidence.

The system records the appeal in the audit log and changes the submission's status to under_review. The student receives a confirmation that their appeal was recorded. The original prediction is not automatically changed.

## 4. The two endpoint shapes

### `POST /submit`

**In:**
The /submit endpoint accepts a JSON request containing two fields:

- text: The writing that the user wants to analyze.

- creator_id: A unique identifier for the writer submitting the text.

Example request:
```json
{
  "text": "This is my original essay about the importance of education.",
  "creator_id": "student123"
}
```
**Out:**
The endpoint returns a JSON response containing:

- content_id: A unique ID assigned to the submitted writing.

- guess: The system's prediction of whether the text is AI-generated or human-written.

- confidence: A number between 0 and 1 indicating how confident the system is in its prediction.

- label: A plain-English explanation of the prediction.

- status: The current status of the submission.

Example response:
```json
{
  "content_id": "content001",
  "guess": "human",
  "confidence": 0.85,
  "label": "Our system believes this writing was probably written by a person.",
  "status": "completed"
}
```
The system also records the submission and its detection scores in the audit log.

### `POST /appeal`

**In:**
The `/appeal`  endpoint accepts a JSON request containing two fields:

- `content_id`: The unique identifier of the submission being appealed.

- `reasoning`:  The writer's explanation of why they believe the prediction is incorrect.

Example request:
```json
{
  "content_id": "content001",
  "reasoning": "I wrote this essay myself and have earlier drafts to prove my work."
}
```

**Out:**
The endpoint returns a JSON response confirming that the appeal was recorded and the submission is under review.

Example response:
```json
{
  "content_id": "content001",
  "status": "under_review",
  "message": "Your appeal has been recorded and is awaiting review."
}
```
The system saves the appeal information in the audit log and updates the submission's status to under_review. It does not automatically change the original prediction.
